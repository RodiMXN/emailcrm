# UI Customization Principles

## Purpose

This document defines how the Twenty UI should be adapted for the email CRM.

The goal is to preserve the fresh, modern, clean look of Twenty while simplifying the product to fit the outbound lead monitoring workflow.

---

## Core Principle

Keep the existing Twenty visual design wherever possible.

Do not redesign the interface unless absolutely necessary.

Prefer:
- hiding unused actions
- hiding unused navigation items
- renaming labels
- repurposing existing screens
- adding custom lead-state fields and workflow controls

Avoid:
- redesigning layout
- changing colors unnecessarily
- replacing core UI components
- rebuilding list/detail page experiences from scratch

---

## UI Strategy

The product should continue to feel like Twenty visually, but operate like an email-first outbound CRM.

This means:
- preserve the current visual shell
- preserve modern table and detail layouts
- preserve the clean sidebar and overall styling
- reduce clutter by removing irrelevant buttons and modules
- make lead state and next action the most visible workflow elements

---

## Keep

- overall color palette
- typography
- spacing
- list view styling
- detail page styling
- navigation shell
- filters and search where useful
- record page layout patterns

---

## Simplify

- remove buttons not used in the email workflow
- hide modules not needed for outreach monitoring
- remove confusing CRM concepts from daily operator views
- reduce available actions to only the most useful ones

---

## Add

- state badge
- next action badge
- next action date
- parked until
- form status
- suppression reason
- event timeline focused on outreach activity

---

## Design Goal

The final product should feel like:
- a clean modern SaaS interface
- a focused outbound operations tool
- a simpler, sharper version of Twenty

It should not feel like:
- a bloated general CRM
- a custom internal tool with rough design
- a completely different product visually
